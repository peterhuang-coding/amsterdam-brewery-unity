## 地图数据与限制

数据版本为 `amsterdam-shape-d30-v1`。地图取自现有 Kadaster / PDOK BGT 提取物（CC0-1.0），离线简化轮廓；店铺是虚构游戏地点，精细源数据不进入浏览器。可通行网格独立于展示形状生成，不把水域当作陆地。Lotte 使用真实桥头地面 anchor `(1059.5,3256.5)`；d29 存档只定向迁移旧 Lotte 到达范围内的角色、自行车和出发记录，其他真实米制坐标保留。

总览压缩 1,714,914 字节，五个街区各 27,953–153,038 字节，六份资源合计 2,099,354 字节，另有 2,449 字节清单。资源位于 `tools/prototype/map-data/amsterdam-shape-d30-v1/`，运行时不请求远程 GIS API。需要通过 HTTP 启动。

普通街区连接显示为 3–12 秒虚构短途。局部步速 48 米/秒、骑速 96 米/秒、F3 速度 32 米/秒采用游戏时间比例；身体半径 0.4 米、地点到达半径 4 米、取车范围 2 米。

## 自动化与独立验证边界

新入口测试使用真实 Runtime、DistrictCity、DistrictScene 和小游戏模块；小型五街区资源明确为测试夹具，含真实 gzip 字节、哈希和导航掩码，不是运行时后备地图。覆盖延迟加载、校验失败、取消过期响应、角色/花车独立寻路、渡轮显式登船与暂停、远处自行车、返店与换日重试、刷新不重复结算、窄屏输入和共享画布。

2026-10-27 本轮全量 **575 项 Node、43 项真实几何导航、36 项 Python 地图测试**通过，零失败、零跳过；city＋entry 聚焦回归为 **66/66**（city 29、entry 37）。真实 d30 包测试逐区对比 d29 的形状与导航，并验证 pub↔Lotte 双向精确路线、四向碰撞安全位移和自行车状态；移动测试检查实际消费的转弯折线，不把起终点弦线当作行走路径。2026-10-22 历史冻结基线为 553 项 Node、36 项 Python，更早规则基线为 472 项；旧组件数量与历史加载心跳样本不替代本轮集成验证，也不能当作首屏时间或手机性能承诺。

旧 PubScene 直接几何测试保留为兼容性验证；新入口的地图与非酒馆地点背景使用 DistrictScene。静态缓存复用实际运行时数据对象，不在动画帧重建整份几何数据。

## 2026-10-27 地图修正验证与边界

真实 Chromium 桌面 1440×900／DPR 1 和独立移动上下文 390×844／DPR 2 已完成技术操作验证，未注入坐标、车辆、现金、库存或剧情状态。默认近景中 pub 与 Lotte 同屏可见；桌面地图主列约 760px，行动侧栏保留。自然键盘从全城总览返回近景后产生位移，Lotte 桥头四向可走，pub↔Lotte 真实导航往返、自行车骑／推／再骑、De Pijp 远程目的地与 F3 明确登船后到达 Noord 均实际操作通过。

Lotte 附近暂停刷新保留位置、车辆与经济；在途暂停冻结行程，刷新回到安全出发点，不重复准备或结算。桌面→390→桌面 resize、真实 DPR 2、marker hit-test 与中间桌面宽度 801、851、1101、1149px 均无横向溢出；两端最终 console 均为 0 error／0 warning。

后续规格复核补出一个入口遗漏：先主动切到街区全景，再按 E 进入地点、按 B 返回时，镜头仍是 fit。新增回归先在旧实现上以 `'fit' !== 'street'` 失败；最小修复只在 `city-bike` 从地点面板退出时调用现有 `useStreetView()`，地图模式下主动选择的全景不被 B 重置。同一回归随后通过；真实 Chromium 沿全景→E 进入 `Tweede Kans`→B 返回的自然路径确认恢复 street／local，截图显示跟随近景，实际 console 为 0 error／0 warning。真实窄路面保持既有 `pushing:true` 语义，未改车辆或碰撞规则。

旧 `test.html` 浏览器套件历史为 **897/915 通过（18 项失败）**，本轮未重跑，也未将其改写为全绿。主线已复核本轮生产和测试 diff；原规格代理在核对 RED／GREEN、575／66 等最终日志和真实浏览器证据后，focused re-review 结论为 **SPEC COMPLIANT，七项技术规格通过，当前无必须修复项**。独立质量复核未形成最终结论，不记为质量批准。上述自动化和浏览器技术操作不等于用户真人试玩体验验收；实体手机、公网性能、全部剧情组合和长期趣味仍未验证。
