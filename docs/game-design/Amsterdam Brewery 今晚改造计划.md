# Amsterdam Brewery 今晚改造计划

> 截至 2026 年 9 月 14 日，今晚的目标已经从“继续扩玩法”收敛为：做出一个能验证核心假设的三日纵向切片，并把后续设计、待办和小游戏候选完整归档。本文描述当前状态，不把策划项写成已实现功能。

## 一、今晚验收目标

玩家使用任意 Seed 开始后，可以完成以下闭环：

```text
看到第三天的节庆订单
→ 在有限时段中选择快熟或慢熟路线
→ 酿酒只生成真实批次，不直接发钱
→ 慢熟批次在第二天出现可解释的偏差
→ 玩家在减量保质和风味转向之间选择
→ 决定参加课程还是保留下午经营时间
→ 向散客出售，或在第三天按约/替代交付
→ 形成现金、关系、学业与批次经历的并列回顾
```

这条闭环的验证目标不是证明完整游戏已经好玩，而是回答三个问题：

1. 玩家是否会因为未来需求改变今天的安排；
2. 出现偏差后，是否愿意改线继续，而不是直接重开；
3. 第二局是否会主动尝试另一条酿造和销售策略。

## 三、当前代码落点

| 文件 | 职责 |
| --- | --- |
| `tools/prototype/core-loop.html` | 三日试玩界面、操作入口、批次与因果展示、记录导出 |
| `tools/prototype/core-loop.js` | 独立规则模块、Seed、时间、批次、订单、销售与结局 |
| `tools/prototype/test-core-loop.js` | 核心规则回归测试 |
| `tools/prototype/index.html` | 七日原型与三日试玩的入口连接 |

三日试玩故意不继承七日模式的 Meta、产业倍率和随机收益，避免无法判断玩家选择究竟来自核心机制还是旧加成。

## 四、今晚不继续扩的内容

- 不把二十二项玩法全部实现；
- 不重写 Unity 版本；
- 不拆分旧七日单文件原型；
- 不继续扩咖啡、SmartShop、冲浪、学术和派系数值；
- 不实现完整偷窃、逃票和追捕；
- 不引入在线服务器依赖；
- 不把国王节与 Pride 塞进同一个真实连续七日主题周。

当前六时段仍为 `Dawn / Morning / Afternoon / Evening / Night / LateNight`，没有 `Noon`。正式七日设计应在迁移时统一确定生活语义，不能直接套用旧草案中的时段编号。

## 五、下一步顺序

```text
三日真实试玩
→ 修正信息表达与明显支配策略
→ 加第二种主题周或第二类限时订单
→ 接菜单与常客承诺
→ 加少量有代价的规则卡
→ 再决定是否扩合法采购与灰色来源
```

详细任务、验收方式和后置范围见[当前玩法待办](Amsterdam%20Brewery%20当前玩法待办.md)。
