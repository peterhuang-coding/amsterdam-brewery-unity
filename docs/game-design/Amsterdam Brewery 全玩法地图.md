## 二、活动容器

活动本身不是第二套小游戏，只向现有玩法注入规则：

| 活动 | 日程改写 | 主要受影响玩法 |
|-|-|-|
| Pride/LGBTQ+ 节庆 | 早放、夜间延长、部分道路拥堵 | 采购、路线、菜单、酒吧、节庆摊位 |
| 国王节 | 停课、全天街头活动、交通大改 | 路线、跳蚤市场采购、偷窃、酒吧、摊位 |
| 博物馆夜 | 白天照常上课、夜间特殊客群 | 学业、菜单、酒吧、NPC |
| 考试周 | 复习和考试占用课余窗口 | 排程、采购、学业、酒吧备货 |
| 啤酒节 | 集中检验品质、产量、来源和品牌 | 酿酒、库存、节庆摊位、终局评审 |
| 恶劣天气 | 通勤延时、供应变化、冲浪关闭或强化 | 路线、采购、酒吧、冲浪 |
| 检查周 | 提高灰色行为的持续风险 | 逃票、偷窃、销赃、追捕、终局 |

## 三、组合原则

```text
Run Seed 选择活动与课表
→ 日程生成玩法入口
→ 玩家选择合法、灰色或放弃行动
→ 小游戏写回各自所属状态
→ 状态修改未来事件 Deck
→ Day 7 读取整局轨迹
```

- 经营小游戏共享批次、库存、现金、需求和 Heat。
- 学业只共享时间冲突与人物叙事，不读写酿酒数据。
- 冲浪只共享日历和可用时间，其他资源完全独立。
- 活动同时修改两个以上维度，才算有效活动。
- 同一操作小游戏可以被多种活动换皮和改规则，但不能只换美术。

## 四、MVP 切片

当前第一步先用独立三日试玩验证：

```text
公开订单 → 快熟/慢熟酿造 → 批次抢救
→ 散客销售/限时交付 → 三日因果回顾
```

三日闭环通过真实试玩后，再迁回七日结构，接入菜单、常客承诺、深夜结算和 Day 7 啤酒节；随后加入合法采购与灰色来源。逃票、追捕、关键学业挑战、节庆摊位属于第二层。Coffeeshop、SmartShop 和冲浪作为独立扩展，不作为核心循环成立的前提。
