# NPC谈判请求与承诺

## 定位

让关系成为“改变规则与制造未来义务”的系统，而不是送礼进度条。

## 准入与时长

课间、放学后、酒吧特殊顾客或活动地点触发，单次 20—60 秒。

## 输入

- NPC 当前诉求、底线、已有关系和未兑现承诺；
- 玩家可提供的时间、批次、物品、现金或信息；
- 活动背景与未来日程冲突。

## 决策循环

1. **读诉求：** NPC 明说目标，但保留一个偏好或顾虑。
2. **提方案：** 在立即交换、延期承诺、共同承担风险和拒绝之间选择。
3. **定条款：** 明确交付日、允许替代的内容和失败后果。
4. **写入日历：** 承诺自动成为未来时间块或事件牌。

## 随机性

NPC 诉求受 Seed 和活动影响；关系提高信息透明度，不保证对方接受所有条件。

## 结果层级

- 双赢协议：双方获得明确价值；
- 延迟承诺：当前省资源，未来锁时间；
- 风险共担：NPC 提供掩护，但会索要更大回报；
- 礼貌拒绝：关系不变或小幅下降；
- 失信：修改人物关系和后续事件，不只是扣好感。

## 活动变体

Pride 出现联名、志愿和团体订单；国王节出现摊位与街头采购关系；考试周同学更关注协作；检查周地下 NPC 提高掩护价格。

## 系统边界

NPC 可以修改规则、提供入口和承担风险，但不能成为无条件解决所有系统的万能钥匙。

## MVP

三个核心 NPC、每人一个目标/底线/特殊规则、承诺日历和失信事件。
