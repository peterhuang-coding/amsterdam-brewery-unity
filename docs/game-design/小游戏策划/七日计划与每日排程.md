# 七日计划与每日排程

## 定位

它是每个 Run 的决策入口，不是日历 UI。核心乐趣是看见未来冲突后提前下注：哪天缺课、哪天备货、哪天承担现金风险。

## 准入与时长

- Run 开始时进行一次七日粗排程；
- 每晚结算后进行一次次日微调；
- 单次 20—40 秒，不能拖慢日循环。

## 输入与输出

| 输入 | 输出 |
|-|-|
| 大型活动、课表、截止日期 | 强制时间块 |
| 三日天气与交通预报 | 可用行动窗口 |
| 当前库存、现金、Heat | 玩家设置的优先事项与备选计划 |

## 操作循环

1. **读冲突：** 系统突出显示课程、活动、酒吧需求和供应变化的撞车点。
2. **放锚点：** 玩家标记必须完成的一到两个目标，例如周三采购酒花、周五保留完整晚间营业。
3. **设预案：** 为高风险目标选择失败替代，例如采购失败则改用替代配方。
4. **接受代价：** 系统明确显示缺课、库存不足、债务或 Heat 的预期变化。

## 随机性

大型活动与课表开局公开；小型事件只展示类别。玩家的预案不会锁死结果，只会在事件发生时提供更好的应对选项。

## 结果层级

- 完整执行：获得计划连贯奖励，但不直接加数值；
- 部分执行：保留核心目标，放弃次要事项；
- 被迫改线：活动或事故改变当天路线；
- 主动撕毁计划：获得即时收益，同时积累学业、债务或关系代价。

## 活动变体

考试周增加强制复习块；国王节把全天改成活动块；Pride 可能早放但延长夜间营业；检查周让灰色行动预案显示更宽的风险区间。

## 系统边界

排程只分配时间和预案，不替玩家自动完成行动，也不因为“排得好”直接提高酿酒品质。

## MVP

七天横轴、五种时间块、两个可标记目标、一个失败预案槽、三种冲突提示即可。
