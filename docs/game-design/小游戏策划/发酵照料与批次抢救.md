# 发酵照料与批次抢救

## 定位

把酿酒后的等待期变成跨日承诺：玩家需要在时间、品质、产量和目标风味之间止损，而不是被动等倒计时。

## 准入与时长

批次进入关键节点、设备报警或随机事故时触发，单次 30—90 秒；普通批次只显示短决策。

## 输入

- 批次当前标签、温度轨迹、完成度和缺陷；
- 设备状态、可用工具和剩余时间；
- 当晚库存缺口与未来活动需求。

## 操作循环

1. **诊断信号：** 从气味、泡沫、温度和历史记录中判断问题类别，信息不完全但方向可读。
2. **选择目标：** 保品质、保产量、赶时间或主动改造成另一种酒。
3. **执行干预：** 调温、延时、分桶、混合、提前终止或接受缺陷。
4. **锁定后果：** 更新标签、产量、完成时间和下一次事故牌组。

## 随机性

隐藏问题只从已有风险演化，不凭空出现。投入设备、时间或牺牲产量可以缩小结果区间，但不能保证完美。

## 结果层级

- 稳定完成：保留目标标签；
- 风味转向：失去原目标但形成新用途；
- 降产保质：数量减少，品质维持；
- 保量降质：适合低价、混合或派对客；
- 延期：错过当晚销售，但可能赶上后续活动。

## 活动变体

热浪提高温控压力；啤酒节前一天让“延期”代价巨大；库存短缺会诱导玩家提前终止；停电事件迫使在多个批次之间分配设备。

## 系统边界

抢救只能改变批次自身数据，不能通过学业资源消除风险。任何失败都至少保留一种后续用途。

## MVP

四类事故、六种干预、五级结果、完成日变化和与酒吧库存的明确预览。
