# 地窖库存与批次分配

## 定位

这是短时组合决策：同一批酒该今晚卖、保留到节庆、混合、送人还是承担过期风险。

## 准入与时长

酒吧开门前、批次完成时和深夜盘点时进入，单次 20—45 秒。

## 输入

- 每个批次的数量、品质、标签、来源和保质期；
- 今晚客群、未来活动预报与合约；
- 储存容量、冷藏状态和现金压力。

## 决策循环

1. **看缺口：** 比较现有库存与今晚菜单、未来终局需求。
2. **分配用途：** 上架、保留、混合、送 NPC、地下转售或报废回收。
3. **处理容量：** 地窖满时必须牺牲一个批次的未来价值。
4. **锁定来源：** `stolen`、`laundered`、`unlicensed` 不会因移动库存自动消失。

## 随机性

库存本身无骰子；随机性来自未来预报不完整和批次保质期事件。玩家必须能看到最坏结果。

## 结果层级

- 精准匹配：今晚和未来活动都有库存；
- 现金优先：出售高潜力批次缓解债务；
- 终局优先：牺牲当前收入保存比赛酒；
- 容量失误：被迫低价清仓或混合；
- 来源暴露：高风险批次进入正式菜单后提高检查后果。

## 活动变体

啤酒节增加保留槽；Pride 和国王节提高大批量消耗；检查周要求单独管理来源风险。

## 系统边界

库存分配不做物理搬箱操作，不产生独立货币或经验。

## MVP

六个批次槽、五种用途、保质期、来源标签和未来两日需求预览。
