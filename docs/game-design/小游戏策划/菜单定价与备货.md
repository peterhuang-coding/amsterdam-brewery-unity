# 菜单定价与备货

## 定位

把市场情报转化为当晚承诺。菜单不是静态商品列表，而是玩家对客群构成的判断。

## 准入与时长

每晚开店前固定触发，单次 30—60 秒。

## 输入

- 可售批次、数量、品质、标签和来源；
- 预报客群、活动需求与价格弹性；
- 酒杯、服务能力、促销槽和特殊订单。

## 决策循环

1. **选择主打：** 从库存中选 2—4 个上架批次。
2. **设价格：** 在走量、平衡、高价和限量之间选择。
3. **分配备货：** 决定每种酒预留多少，是否锁定给特殊顾客或终局。
4. **设一条规则：** 欢乐时段、套餐、会员优先或拒售高风险批次。

## 随机性

客群只给范围和偏好，不给精确人数。关系和前几晚反馈可以提高预测准确度，但不能完全消除市场波动。

## 结果层级

- 命中市场：库存周转和评价平衡；
- 高价少卖：现金单价高但剩货多；
- 低价售罄：现金稳定但错失未来价值；
- 菜单错配：顾客改点、离店或触发替代需求；
- 来源冒险：高风险酒带来高价地下客或检查隐患。

## 活动变体

Pride 偏好分享装、果香和低酒精；国王节偏好便携、大批量；博物馆夜偏好限量和故事性；考试周偏好便宜和快速服务。

## 系统边界

菜单只设定策略，不替代酒吧服务操作。定价不能凭空创造客群。

## MVP

四个菜单槽、四档价格、一个促销规则、客群范围预览和来源风险提示。
