# 设备维修

## 定位

用有限时间恢复设备能力或做临时改装，让设备故障成为 Build 分叉而不是纯罚款。

## 准入与时长

放学后、深夜轻维修或设备事故时触发，单次 30—75 秒。

## 输入

- 故障设备、受影响功能和严重度；
- 工具、备件、现金、维修关系和剩余时间；
- 近期酿造计划与活动需求。

## 操作循环

1. **诊断：** 从三到四个症状中识别故障类别。
2. **选目标：** 完全修复、临时维持、牺牲容量换稳定或做风险改装。
3. **布置资源：** 将有限工具分配到关键节点，形成小型连线/优先级谜题。
4. **压力测试：** 决定现在停手，还是继续提高性能并承担复发风险。

## 随机性

症状顺序变化，但每种故障遵守稳定逻辑。维修记录会逐渐揭示设备弱点，不依赖学术小游戏。

## 结果层级

- 完全修复：恢复基础参数；
- 临时修复：撑过一次酿造，之后必需再处理；
- 定向改装：一项增强、一项削弱；
- 错误诊断：损失时间和备件；
- 带病运行：允许继续，但向相关事故池加入卡牌。

## 活动变体

啤酒节前维修时间更紧；热浪提高温控设备压力；供应短缺让替代零件产生独特改装；停电形成多设备优先级事件。

## 系统边界

维修只影响设备参数，不直接提高酒的品质或产生现金。

## MVP

三类设备、四类故障、四种处理路线、临时修复倒计时和事故池联动。
