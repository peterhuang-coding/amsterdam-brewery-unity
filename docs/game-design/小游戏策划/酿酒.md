# 酿酒

## 定位

酿酒是核心转换引擎：把带标签的原料、设备条件和玩家选择转换成一个可追踪的批次。它不直接产钱。

## 准入与时长

拥有可用设备、足够原料和完整操作窗口时进入，单次 90—180 秒。课间不能启动完整酿造，只能查看状态或准备原料。

## 输入

- 麦芽、酒花、酵母、添加物及其来源标签；
- 设备容量、清洁度、稳定性和临时改装；
- 配方笔记、目标风味和计划完成日；
- 天气、供应环境与当前时间窗口。

## 操作循环

1. **配方 Draft：** 从现有原料中组合基底、主风味和风险来源，并预览可能标签范围。
2. **工艺路线：** 在稳妥、快速、抢香、高产等路线中逐段选择，不做单纯按点 QTE。
3. **资源分配：** 决定把设备精度、额外时间和稀缺添加物用在哪个阶段。
4. **封批：** 为批次命名，确认产量、预计完成时间和已知风险。

## 随机性

每种原料有公开主标签和一个可逐渐识别的次级特性。事故牌只从当前配方相关的牌池抽取，设备、天气和操作会改变权重。

## 结果层级

- 精准命中：目标标签清晰，风险低；
- 意外佳作：出现非预期但可利用的标签；
- 可救偏差：进入发酵抢救并提供多种方向；
- 次品：品质低但仍能混合、低价售卖或转地下用途；
- 报废：仅在连续忽略警告后发生，并返还少量可回收资源。

## 活动变体

Pride 提高彩色、果香、分享装需求；国王节偏向大批量和便携；啤酒节提高品质和来源要求；热浪改变发酵风险但不直接判定失败。

## 系统边界

Academic 不检测或修复批次。玩家通过原料说明、配方笔记、设备、试饮和历史经验提高可控性。

## MVP

三种基础酒型、八种原料、六个工艺选择、十二张相关事故牌、批次标签和完成时间。
