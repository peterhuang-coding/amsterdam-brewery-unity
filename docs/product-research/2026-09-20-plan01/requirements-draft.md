# 需求细化文档：Tweede Kans 三天 Web 原型的城市夜探闭环

## 1. 目标与体验闭环

本轮目标不是继续堆叠互不相关的地点小游戏，而是验证“每次出门都有不同操作与发现”的城市夜探核心循环。用户以《潜水员戴夫》的体验为类比：夜探对应潜水，白天旅游城市对应准备、观察与承接后果的表层。当前产品仍应聚焦“三天 Web 原型”，不是 Unity 完成品，也不是完整社会模拟或 DLC 立项。

目标闭环可概括为：

1. **白天获得情境与准备**：在旅游城市中步行、骑车、进店、免费打听规律或选择有限准备；玩家看见城市的旅游面。
2. **夜里进入连续城市背面**：在同一张连续夜探地图上移动、观察、选择路线，而不是进入一组彼此割裂的小游戏。
3. **用统一行动处理变化**：移动、钩取、引声、拖桶、泡沫、背包管理、机关互动在多地点复用；地点差异来自空间、障碍、节拍、路线与代价，而非只换一套操作。
4. **在压力下做取舍**：180 秒单趟时间、容量、工具、受伤、超时、入口与后门、是否继续深入或提前回家共同形成决策。
5. **回家产生次日回响**：主动安全撤离后一次性入库；行动可能形成告示、传闻、开放捷径、修泵、人物到店等后果，再影响下一晚是否出门、带什么、走哪里。

“探索”的成立标准应是：玩家能在第二趟根据第一趟经验改变路线、工具或撤退计划；失败时能理解原因并提出另一种打法。相反，如果差异主要来自文案随机、地点只是按钮列表、或每个地点都要重新学一套互不复用的小游戏，则核心闭环不成立。

当前已采用的操作形态是**自动行进加关键选择，随时可切手动**。这是原型事实，不应在下一轮被替换成全自动播放或纯路线卡，也不应未经决策迁移 Unity。

## 3. 固定需求细化

### REQ-01 统一且可重复的城市夜探循环

**玩家问题**
玩家为什么今晚要出门？为什么明晚还要再出门？如果每次只是点地点、看文案、领取奖励，探索会很快变成重复劳动。

**已有基础**
README 显示已有连续夜探地图、统一移动/钩取/引声/拖桶/泡沫、三工具、三晚局势、种子变化、180 秒时限、双撤离口、自动关键选择与手动切换。代码摘录显示新趟 version 4、duration 180，关键事件会停止模拟，路线可切换，stuck 有反馈。

**最小候选增量**
不扩新城市，先围绕现有区域做一份“路线—机会—代价—后果”复盘表，并选择一个有界实验：在现有三晚中让同一目标至少存在两种可理解打法，例如快速直达、绕路开捷径、利用声音或拖桶创造安全窗口。重点观察玩家是否会主动改道，以及能否解释第二次出门的理由。

**范围外**
不新增大量工具，不做程序生成全城，不把夜探拆成独立小游戏大厅，不延长 180 秒，不改变现有自动关键选择的基本形态。

**可观察结果**
同一玩家或观察者可看到：第一趟选择、遭遇的阻碍、撤退结果；第二趟前能说出改变的工具、路线或时机；实际行动与复盘一致。建议记录小样本试玩，阈值与样本数均为建议，不冒充玩家研究。

**负面反例**

- 反例一：新增十个地点按钮，但每个地点只是“等待—获得物资—结算”，没有统一空间决策。
- 反例二：玩家每次都机械点击收益最高路线，工具和捷径从不影响选择。

### REQ-02 白天线索、夜间行动、次日经营与城市后果

**玩家问题**
白天踩点和夜里行动应当相互记得。若白天只是领资源、夜晚只是搬东西、次日只显示数字，玩家不会感到自己在同一座城中活动。

**已有基础**
README 显示市场卸货路线、Bram 节拍、实验室规律可在白天免费打听，并写入地图背面；夜里搜货、开捷径、拿冷藏箱会留下次日告示或传闻；温室修泵后此后每夜路面保持干燥但出售少 €5；Noor 或打听箱子的人会在下次营业出现。代码摘录显示 summary 后才能 explore、撤离后 `explore_return` 一次性入库并追加最多 3 条 journal，经营 report 已在打烊结算。

**最小候选增量**
做一个极小因果链梳理与补齐：白天可观察或打听到一个规律；夜里有至少两种利用方式；次日经营或城市状态出现可见反馈；反馈再提示下一晚机会。优先利用现有卸货门、节拍、修泵、Noor、花与客人耐心，不先合并独立经营内核。

**范围外**
不做全城 NPC 作息模拟，不把所有探险收益强转为酿酒材料，不让不出门必然失败，不修改已结算营业账。

**可观察结果**
玩家能在白天指出“我为什么知道这条路/时机”；夜里行动后，次日能在店铺、人物或场景中看到对应变化；玩家能据此规划下一晚。

**负面反例**

- 反例一：白天线索只是一句 flavor text，夜间是否读过线索没有差别。
- 反例二：所有后果都只表现为金币加减，玩家看不见城市或人物回应。

### REQ-03 地点空间和店内小游戏

**玩家问题**
地点应改变探索方法，而不是用独立小游戏打断主循环。玩家进入店内或后场时，应理解这里和街道共享移动、工具、携带与风险逻辑。

**已有基础**
超市已有三片内部空间和两条路线；NO SIGNAL 有六秒静音/鼓点切换、人群、守卫、等拍；分拣场输送带可停、反转，泡沫可暂停带面；温室有喷淋周期、65% 湿地速度、漂移、阀门、修泵；花店内有配花但不强制小游戏。README 同时说明其他地点尚未完整内部化，白天街景与夜间地图是两张场景。

**最小候选增量**
只选一个当前较弱地点做“服务主循环”的空间补强：它必须提供一种路线改道、一次携带取舍或一个跨日捷径，不新增独立计分玩法。也可以先不新增空间，转而复核分拣场—温室路线中的卡住与教学反馈。

**范围外**
不为每个店铺硬做小游戏，不做节奏游戏化的复杂判定，不把工具名罗列到菜单里充当深度，不扩大到全地图重写。

**可观察结果**
玩家能说出该地点的空间规则如何影响选择，例如等待节拍实际耗时、冷库绕行影响背包或时间、停带/反转影响取货安全；地点结束后玩家仍处于同一套夜探规则中。

**负面反例**

- 反例一：进入地点后切换成与移动、工具、背包完全无关的新积分小游戏。
- 反例二：店内空间视觉上更大，但所有路线到达同一奖励且无代价差异。

### REQ-04 人物关系与城市社交

**玩家问题**
人物不应只提供好感度或笑话。玩家应感到人物有欲望、立场、成本和后果，关系会改变信息、入口、路线或下一次见面。

**已有基础**
Lotte 收花、留黑啤承诺会影响后续顾客耐心和小费；Noor 的冷藏箱委托可跨日保留，并在下次营业作为顾客出现；房东、网红、检查员体现真实费用、制度荒诞和选择代价。但完整人物三日链、大规模声望系统未实现。

**最小候选增量**
以少量熟人为界，优先选择 Noor 或 Lotte 中一人补齐“白天信息—夜里选择—次日店里反馈—再下一晚机会”的短链。幽默应来自制度、成本、承诺与处境，而不是追加段子或羞辱弱势角色。

**范围外**
不做大量随机路人，不搭庞大声望阵营，不做独立成人服务玩法，不把关系简化成纯折扣机器。

**可观察结果**
一次承诺或拒绝会改变之后可走的路线、可得信息、人物态度或经营事件；玩家能理解角色为什么这样反应。

**负面反例**

- 反例一：送礼后只显示好感 +1，没有任何行动空间变化。
- 反例二：笑点与角色处境无关，只是在事件文案中堆笑话。

### REQ-05 大地图、街区、自行车与 2.5D 表现

**玩家问题**
更大的地图必须带来新的路线判断。自行车、花、地标和街区应帮助玩家理解城市结构与携带取舍，而不是只增加跑路面积。

**已有基础**
README 显示白天已有七地点、运河桥、渡轮、自行车骑/推/停、刷新保存；花束可手持或存前篮，只能在车旁取放，不能隔街送出车篮花；大地图与跟随镜头、景点手册、最近三趟夜探记录已存在。最终 2.5D 街景和产品交互未定稿。

**最小候选增量**
先做一个代表街区的地图分层方案，明确白天大地图、夜间连续地图、店内空间、自行车可达点、停车点与撤退口的关系。若做实验，只比较宽路骑行、窄桥下车、携花或携货绕路三种策略，不扩成 DLC。

**范围外**
不立即制作全量城市，不把地标的数量增加当成玩法深度，不批准 DLC，不决定 Unity，不改变自行车已给数值，除非另行明确。

**可观察结果**
玩家能解释何时骑车、何时停车、带花或货物为何影响路线；地图扩展后，迷路和跑路不应成为主要难度，路线取舍才是主要难度。

**负面反例**

- 反例一：最佳策略是全程骑车，停车、携物、窄桥都没有实际取舍。
- 反例二：新增多个景点地标，但只展示介绍文字，不影响探索或回城决策。

### REQ-06 可理解交互、可靠性、存档和可验证性

**玩家问题**
玩家需要知道自动模式为何停下、为何卡住、哪些行为不可逆、刷新后是否保留进度。自动测试可验证规则，但不能替代玩家觉得可理解、有趣。

**已有基础**
README 显示键鼠和按钮覆盖、暂停、帮助、窄屏适配、确定性、存档恢复、旧版本迁移、非法存档提示；历史 Node 与 Playwright 验收较完整。代码摘录显示自动关键事件停止模拟，遇 stuck 有反馈。当前基线本轮未重新试玩；ALG01 分支曾在 24 条路线中 23 条撤离，seed6/day1/hook 出现卡住，尚未在可玩基线复核。

**最小候选增量**
先对当前 SHA 做有界复核：跑通既有自动测试与一条浏览器手动链路，并最小化已知卡住案例；补充暂停原因、阻塞原因、选择后果的可观察反馈。任何修复需另行批准，不能把 ALG01 整支自动合入。

**范围外**
不重试失败、不切换平台、不按量调用 API、不重写存档系统、不把自动化路线通过率等同于趣味验证。

**可观察结果**
玩家在自动暂停、无法通行、容量不足、危险接近、撤离结算时能理解当前状态；刷新后进行中探险暂停并可恢复；失败可复盘而非表现为无响应。

**负面反例**

- 反例一：角色停住但界面不说明是障碍、等待选择还是寻路失败。
- 反例二：自动模式绕过玩家确认，直接交付箱子、丢弃物资或触发不可逆后果。

## 4. 下一轮方向比较与候选推荐

以下均为候选，不是批准。

### 方向 A：夜探核心闭环复核与卡住最小化

**成本**：低至中。主要基于当前可玩基线，不扩地图、不合并分支；需要测试、复现、定位与少量交互文案或规则修正。

**依赖**：当前 SHA、现有测试、浏览器手动验收；可参考 ALG01 的卡住案例，但不直接合入。

**可证伪条件**：

- 若当前基线稳定，且试玩者仍不知道为何改道，则可靠性不是主要瓶颈，应转向 B。
- 若卡住只出现在 ALG01 而当前基线不可复现，应关闭该技术线索，避免伪修复。
- 建议以小样本人工试玩观察停顿理解和主动改道，样本数与阈值均标为建议。

**优点**：范围有界，直接保护已有自动关键选择和恢复体验。
**风险**：只能修稳，未必显著增加重复出门欲望。

### 方向 B：补强一条“白天线索—夜间改道—次日反馈”的短闭环

**成本**：中。不大拆系统，选择现有人物、地点或捷径，补齐因果可见性和第二晚决策。

**依赖**：现有白天线索、夜探行动、journal、次日告示/人物到店、经营结算；不依赖 407697b 合并。

**可证伪条件**：

- 玩家读完线索后仍不能在夜里采取不同行动，说明只是文案。
- 次日反馈出现后，玩家不能或不愿据此调整第二晚路线，说明闭环不足。
- 如果最优路线固定，或不做支线无法通关，应回退收益设计。

**优点**：最直接服务“第二次出门的理由”，且能避免小游戏堆叠。
**风险**：若反馈只落为金币，容易退化成任务奖励。

### 方向 C：一个代表街区的空间/自行车路线实验

**成本**：中至高。需要梳理大地图、小街区、自行车、停车、携物与撤退关系；若触碰视觉表现，成本会上升。

**依赖**：现有城市地图、自行车、花店、夜间地图；最终 2.5D 交互未定，需要限制素材范围。

**可证伪条件**：

- 玩家始终骑车或认为停车只是麻烦，规则应简化。
- 新街区只增加跑路时间和地标数量，不产生携带、时机或撤退取舍，则不应扩图。
- 若一个代表街区都无法说明主地图/小地图关系，不应提前做 DLC 或全量地图。

**优点**：为后续城市规模和表现方式探路。
**风险**：容易提前进入制作量扩张，掩盖核心循环尚未验证的问题。

### 候选推荐

建议下一轮优先 **A + 一个极小 B 切片**：先在当前可玩 SHA 复核稳定性和已知卡住，再选择一条已有因果链做可理解性补强，例如“市场/咖啡馆线索—夜间路线选择—次日告示或人物反馈—第二晚捷径/风险变化”。暂不推荐先做 C 的扩图，也不推荐合并经营分叉、迁移 Unity 或批准 DLC。

该推荐不是实现批准；若要执行，仍需明确选择的短链、基线、停止条件与验收方式。
