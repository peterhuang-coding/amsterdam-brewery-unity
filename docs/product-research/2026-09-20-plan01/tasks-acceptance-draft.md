# 任务拆分与验收矩阵（候选规划，仅文档）

本文件基于固定需求 REQ-01 至 REQ-06、当前可玩源码基线 `78b13c06a5df7914fbbb4eb404bec6489b7376cb`、独立算法分支事实与同版本 README 编制。当前轮次只做任务规划，不改代码、不运行测试、不声称已复现或修复，也不把既有过桥、温室、背包、自行车、地点深化等能力重新当作待造功能。

## 一、事实边界

- 当前可玩版：`78b13c0`，三天 Web 原型；README 记载历史 Node 97/97 与浏览器证据，但本轮未重新试玩，不能把历史证据当成本轮新测。

- **关联 REQ**：REQ-01、REQ-06。
- **类型**：核验。
- **明确输入**：`78b13c0` 干净工作树；README；`backstage-core.js`、`backstage-auto.js` 与相关测试；`c764eb0` 的实验记录，仅作为线索。
- **范围外**：不合入算法分支；不采用其路线优化；不修改搜索脚本；不把 23/24 记录写成当前版通过；不直接重构寻路或自动系统。
- **交付物**：基线能力清单、证据分层表、seed6 复核步骤、最小复现输入、实际/待复现状态、影响范围判断、是否需要修复的决策材料。
- **依赖**：无。
- **验收步骤与失败判据**：
  1. Given 当前工作树为 `78b13c0`，When 查看源码与版本记录，Then 文档明确区分“可玩基线已做”“算法分支未合入”“历史测试存在但本轮未跑”。
  2. Given seed6/day1/hook 的路线记录为 `club→take-hook→garden`，When 在批准后的复核环境按相同种子、日期、工具和输入操作，Then 才记录是否卡住；若未复现，必须标记为“基线未复现”，不能硬造失败。
  3. Given 复现成功，When 逐步缩短到最小地点、动作和恢复边界，Then 能判断是交互距离、寻路、钩取后状态、碰撞还是暂停恢复造成。
  4. Given 自动脚本能通过，When 玩家手动在相同路段接管，Then 仍需检查 UI 是否解释卡住原因和可替代路线；脚本通过不关闭问题。
- **失败判据**：混淆 SHA 或分支；把未合入代码当现状；无复核就声称修复；为修复 seed6 顺带重写自动系统；没有最小复现就进入实现。

### T02 夜探核心循环与“重复出门理由”试玩设计

- **优先级（候选）**：P0。
- **关联 REQ**：REQ-01、REQ-02、REQ-06。
- **类型**：实验设计。
- **明确输入**：现有 2200×1400 连续地图、三晚局势、工具差异、撤离规则、次日 journal、Noor/温室/捷径等后果。
- **范围外**：不新增地图、不新增工具成长线、不做完整随机城市；不以文案变化替代操作变化；不设定留存目标。
- **交付物**：三局短试玩脚本、观察表、路线分歧复盘模板、自动与人工证据分级表。建议每局 10–15 分钟、同一核心流程比较 3 个种子/日期组合，**建议，待确认**。
- **依赖**：T01。
- **验收步骤与失败判据**：
  1. Given 玩家选择长钩、背架或泡沫之一，When 进入同一夜探框架，Then 观察记录其在射程、容量、步速或泡沫恢复上的实际取舍。
  2. Given 玩家在自动路线中遇到搬花工改道询问、拿箱、温室或撤离选择，When 暂停出现，Then 记录玩家是否知道“继续原目标”和“改道”的代价。
  3. Given 玩家满载、时间不足或受伤风险上升，When 需要决定继续还是回家，Then 记录其能否说明撤退损失与保留收益。
  4. Given 第一晚结束，When 次日看到 journal、人物或捷径后果，Then 观察玩家是否能据此提出第二晚策略；若不能，标记为理解或动机问题。
- **失败判据**：只用“按钮可点”“自动路线完成”判定好玩；玩家机械点最高收益而没有改道；三晚差异主要是文案；无人记录失败、放弃和误判原因。

### T03 自动/手动边界、暂停恢复与防卡住验收

- **优先级（候选）**：P0。
- **关联 REQ**：REQ-01、REQ-06。
- **类型**：核验；若 T01 发现明确小缺陷，可在另获批准后产生有限未来实现。
- **明确输入**：现有自动行进、关键事件停止模拟、1×/2×、途中重新选路、随时手动、切回自动重选路线、刷新先暂停、未完成目的地随探险保存。
- **范围外**：不做全自动收益决策；不新增后台模拟；不把不可逆承诺交给自动模式；不重写输入系统。
- **交付物**：自动/手动责任边界表、暂停点清单、恢复状态矩阵、卡住反馈与接管验收用例。
- **依赖**：T01；可与 T02 的文档设计并行，但执行试玩需等待 T01 结论。
- **验收步骤与失败判据**：
  1. Given 自动行进至长路无事件段，When 玩家不操作，Then 角色只执行低风险移动，不自动交付违禁箱、不主动放弃背包、不替玩家做不可逆选择。
  2. Given 到达拿箱、交付、开闸、改道或容量不足决策点，When 弹出选择，Then 人物、物品、冷却和倒计时均暂停；Esc/P 不应隐式选择。
  3. Given 玩家在拖桶、等拍、冷库行进或温室关阀阶段暂停并刷新，When 恢复，Then 位置、工具、库存、任务状态、持续时间、机关状态与待选事件保持一致。
  4. Given 自动寻路遇障碍无法继续，When 出现 stuck 反馈，Then 玩家能停止自动、手动绕开或重新选路；恢复后不得重复丢失已拿物品或重复结算。
  5. Given 玩家从自动切手动再切回自动，When 路线重选，Then 已获得物品、已发现捷径和已消耗时间保留。
- **失败判据**：暂停时计时继续；刷新后重复入库；自动模式承担承诺/丢弃等重大后果；卡住时无反馈或只能刷新；为处理单个卡点改变全部移动规则。

### T04 背包、撤离与跨日一次性结算核验

- **优先级（候选）**：P1。
- **关联 REQ**：REQ-01、REQ-02、REQ-06。
- **类型**：核验。
- **明确输入**：主动西南入口安全撤回、温室后门安全撤回、180 秒收班、受伤三次、主动轻装撤回、归来页一次性入库、最多 3 条 journal、经营 report 已在打烊结算。
- **范围外**：不重做背包 UI；不新增仓库经济；不改变现金/库存安全基线；不合并经营分支。
- **交付物**：撤离结果表、物品流向表、跨日入库幂等用例、夜间收入与已打烊营业账隔离说明。
- **依赖**：T03。
- **验收步骤与失败判据**：
  1. Given 玩家从安全入口携带物资撤回，When 停在归来页尚未点击“收好这一趟”，Then 物品不得提前入库；点击后一次性入库。
  2. Given 归来页已完成入库，When 刷新或重复触发返回，Then 不重复增加库存、现金或 journal。
  3. Given 玩家超时或受伤三次，When 结算，Then 按“保留一半物品件数”处理；家中既有现金和库存不受惩罚。
  4. Given 玩家主动轻装撤回，When 放弃未交付背包，Then 被放弃物不入库；已完成的温室水泵等跨日世界状态仍按既有规则保留。
  5. Given 酒馆经营 report 已在打烊时结算，When 深夜探险后产生跑腿费或收入，Then 独立记录，不回改已结账目。
- **失败判据**：多次点击重复入库；失败撤离影响家中现金；夜间收入改写营业快照；journal 超过上限或与实际到访/行动不一致；安全撤回和获救规则混淆。

### T05 白天线索—夜间行动—次日后果的因果链核验

- **优先级（候选）**：P1。
- **关联 REQ**：REQ-02、REQ-03、REQ-04。
- **类型**：核验与实验设计。
- **明确输入**：市场卸货路线、Bram 节拍、实验室免费规律；线索写在地图背面并带入当晚；无需踩点也能探索；捷径跨日保留；白天线索次日重置；告示、传闻、Noor、打听箱子的人、温室反馈。
- **范围外**：不构建全城作息模拟；不把每个 NPC 做成好感系统；不新增大量随机事件；不把现有资源交换包装成完整社交。
- **交付物**：因果链表、可见反馈清单、“错过/补救”路径表、玩家理解观察题。
- **依赖**：T02；可与 T06 并行设计。
- **验收步骤与失败判据**：
  1. Given 白天在市场免费查看卸货路线，When 当晚进入超市，Then 玩家能获得路线理解或行动提示，且不消耗准备次数。
  2. Given 未进行白天踩点，When 直接夜探，Then 地点仍可进入，但应有信息不足带来的可理解差异，而不是硬锁内容。
  3. Given 玩家在夜店等鼓点穿过人群或用瓶声引开守卫，When 次日查看城市反馈，Then 反馈描述对应行动，不把未发生行为写成传闻。
  4. Given 玩家打开超市卸货捷径，When 跨日再去，Then 捷径保留；普通白天线索按既有规则次日重置。
  5. Given 玩家交还 Noor 箱子或带回箱子，When 下次营业，Then 分别出现 Noor 或打听箱子的人；违禁品不变成酿造材料。
- **失败判据**：后果只表现为不可解释的数字；玩家无法从白天信息预测夜间机会；次日反馈错配；没出门也产生行动传闻；把分支经营订单系统强行并入。

### T06 地点空间与店内小游戏一致性核验

- **优先级（候选）**：P1。
- **关联 REQ**：REQ-03。
- **类型**：核验与实验设计。
- **明确输入**：超市退货货架、冷库、卸货通道；NO SIGNAL 六秒静音/鼓点；分拣场输送带、控制台、反转、泡沫；温室喷淋、湿滑、阀门与修泵；花店自由进入、可选取消。
- **范围外**：不把所有店铺扩成小游戏；不新增无关解谜；不把现有传送带、温室或花店重新开发；不做 Unity 场景。
- **交付物**：地点机制复用表、店内选择与统一夜探操作映射、小游戏节奏/暂停规则、地点深度扩展门槛。
- **依赖**：T02；可与 T05 并行。
- **验收步骤与失败判据**：
  1. Given 玩家进入超市内部，When 选择搜货架、绕冷库或开卸货门，Then 路线由真实空间、碰撞和门状态支持，而非仅播放不同文案。
  2. Given NO SIGNAL 在静音与鼓点间切换，When 玩家选择等待，Then 时间真实流逝；阅读选择时整条街暂停。
  3. Given 分拣场输送带运行，When 玩家近身停带、钩控制器反转或用泡沫覆盖带面，Then 工具效果与移动/货物物理一致。
  4. Given 温室前 6 秒喷淋、后 4 秒间歇，When 玩家走湿地、关阀或修泵，Then 速度、漂移、12 秒临时关阀与永久修泵代价符合现有规则。
  5. Given 玩家进入花店但取消花束，When 离开，Then 不收费、不占每日一次；完成花束才产生 €4 与一次准备消耗。
- **失败判据**：地点小游戏脱离统一移动和工具规则；等待不耗时；机关状态刷新即重置；花店强制消费；新增地点只换皮、不改变路线、携带或时机判断。

### T07 人物关系、欲望与黑色幽默小样设计

- **优先级（候选）**：P2。
- **关联 REQ**：REQ-02、REQ-04。
- **类型**：实验设计；不批准生产实现。
- **明确输入**：Noor 交付与下次营业、Lotte 花/留酒、房东押金、网红样品、检查员手续费、Bram 打工与节拍线索等现有人物/制度情境。
- **范围外**：不做庞大声望表；不增加露骨成人服务；不羞辱弱势角色；不把幽默降级成玩笑堆；不新写完整三日人物链。
- **交付物**：两位熟人的三幕小样、承诺/欠债/信息可信度如何改变入口或路线的示例、两个可补救结局、台词样段、人工笑点与理解观察表。
- **依赖**：T05。
- **验收步骤与失败判据**：
  1. Given 一个人物白天提供身份或需求，When 玩家在夜里发现冲突情境，Then 选择必须影响后续入口、情报、路线或客人，而不仅是好感 +1。
  2. Given 玩家作出承诺但未兑现，When 次日遇到该人物，Then 反馈承认行动后果，并至少提供一种有成本的补救。
  3. Given 玩家选择房东酒抵租、网红样品或检查员手续费，When 阅读结果，Then 笑点来自真实成本、制度荒诞或人物欲望，不依赖说明文字直接告诉玩家“这很好笑”。
  4. Given 自动模拟完成人物事件，When 评估幽默和角色主动性，Then 仍必须由人工试玩判断；自动通过不算趣味通过。
- **失败判据**：关系只剩折扣或数值；人物惩罚无补救；笑点与行动后果脱节；需要完整社会模拟才能成立；未经试玩宣称黑色幽默成立。

### T08 大地图、街区与自行车移动取舍设计

- **优先级（候选）**：P2。
- **关联 REQ**：REQ-05、REQ-01。
- **类型**：实验设计。
- **明确输入**：当前七个地点、运河桥与渡轮、步行/骑车速度、宽桥骑行、窄桥和渡轮推车、停车/取车、车篮花束、连续夜探地图、固定城市布局。
- **范围外**：不重画全量城市；不立即做新 2.5D 街景；不做 DLC 范围；不改变已实现过桥行为；不让自行车成为无代价最优。
- **交付物**：大地图/小街区/室内分层图，一条代表街区的 2.5D 表达低保真方案，三条含停车、携花或撤退取舍的路线比较。
- **依赖**：T06；可与 T07 并行。
- **验收步骤与失败判据**：
  1. Given 玩家在宽路骑行，When 转入窄桥或渡轮，Then 自动推车且车随人走，上岸后恢复骑行；现有停车与刷新位置规则保持可理解。
  2. Given 花束只能手持或存前篮，When 玩家离车，Then 不能隔街取花或送花；该限制应形成路线安排而非单纯阻碍。
  3. Given 未来加入一个代表街区，When 比较步行、骑车、携花绕路，Then 每种方案必须在时间、风险、携带或进入条件上有差异。
  4. Given 2.5D 房屋街景尚未定稿，When 输出低保真表达，Then 只验证视角、遮挡、入口和交互可理解性，不承诺美术规格或引擎迁移。
- **失败判据**：玩家一直骑车且无取舍；停车只是繁琐操作；扩图只增加图标数量；把当前两张白天/夜间场景误称为完整无缝 2.5D；未经批准直接制作大范围地图。
