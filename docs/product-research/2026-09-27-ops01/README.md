# OPS01：持续套餐执行方案，待决定

2026-09-27。用户 D11 询问如何长期交 Coding Plan 做游戏、定时更新并由主代理 review。本轮授权是机制设计；游戏源码、原试玩与每日22:00调度均未更改。CJ01、PLAN01 不恢复。

## 推荐方向

长期按「一个已选玩法目标 → 有界任务 → 套餐暂存执行 → 主代理验收 → 独立分支提交 → 新证据补充任务池」推进。建议目标先定为：重复夜探会改变路线、资源和撤退决定，并在次日产生看得见的后果。有限任务完成后再补新任务；没有有效任务就空闲，不以耗尽 token、文档量或测试数量作为成果。

用户可以一次批准一个有期限的范围：主题、任务类别、文件边界、基线、验收、最大波次与截止时间。范围内的必要拆分由主代理负责，超出范围的候选进入白天决策。当前尚未批准这种持续执行范围。

可补充的六类候选见 [Plan 原稿](backlog-draft.md)：探索遭遇、路线/撤退、昼夜人物后果、经济策略对比、存档恢复、单一缺陷/性能问题。前三类主要增加玩法取舍，后三类提供可信验证。只换文本、未产生新选择的内容不应挤占实现队列。

## 主代理已确定的调度建议，尚未启用

三个方案：保留每天一次检查，操作最少但反馈慢；固定夜间波次与早上回顾，便于控制验收积压；常驻无限循环，当前交接可靠性和并发控制尚不足。推荐第二种，先试两晚。

| 北京时间 | 建议行为 |
| --- | --- |
| 22:00 | 读取最新批准和基线，先收取旧请求、review，再决定是否派发一波 |
| 00:00、02:00 | 同样先收取和review；确认前波结束、无失败且有已批准独立任务，才派发下一波 |
| 09:00 | 只收取、review和给出试玩入口/一个决策点，不补发漏掉的夜间波次 |

继续使用同一个 `amsterdam` heartbeat。每波至多两个独立暂存包、一个父工作项；两个待审包未处理完就停止增发。实际吞吐受任务大小、审查、套餐与本机状态限制；每夜最多三波是上限而非产量承诺。首个两晚试跑应先证明至少一包能完整交回产物、验证和报告，再安排批准范围内的玩法增量。详细执行协议包本轮未提交，所以上表是主代理的调度建议，不是已验证的执行系统。

代码审查需确认基线、允许文件、真实行为与回归；界面变化要真实操作；趣味由玩家试玩判断。自动模拟不能证明好玩。合格代码只进入自己的审查分支并push，不自动合并用户开发分支。每日只报告交付、失败和需决定的问题；未变化时安静。

现行“仅套餐，失败即停、不换Astra或按量API”保持有效。启动失败、unknown、超时、限流或内容验收失败均停止新派发；收取已提交请求，不换ID重发。若未来希望「单个已确认失败任务冻结，其余独立批准任务继续」，那是另一个政策选择，必须明确改变原规则；本方案没有擅自启用它。

## 本轮真实试验与审查

- 计划两份独立短文档，实际只提交任务池包，项目内并发峰值1。另一个项目占用套餐槽位，协议包先等待容量；此后其他项目又启动两路，证明进程检查不是全局并发锁。协议包最终未提交。
- 固定 `doubao-seed-evolving`，一份公开背景输入、600秒/12轮。任务 `amsterdam-ops01-backlog-20260927` 于493.709秒以 `error_max_turns` 退出，缺 `handoff-result.json`。完整交接通过0/1，归档部分稿1份，未提交1份；立即停止，无重试/改派。
- 生成初稿后反复压缩字节数消耗了多次工具调用。过硬格式限制是本轮可见的低效因素；不能据此断定所有历史超时根因。后续交接应以一份最小完整产物和实际验证为主，轻微格式由主代理整理；该改进尚待新授权验证。
- 原背景与暂存背景哈希一致，输出范围未越界；日志存在不在精确命令表内的Bash写稿命令，尽管未产生越界文件，也不能声称命令白名单被可靠执行。暂存目录不等于操作系统沙箱。
- 六类候选可用于讨论，不能直接当实现包：缺少逐项精确文件/命令；卡3与卡5需明确为「角色后果设计 → 存档契约 → 角色实现」；去重应比较触发与实际后果，不应消除所有使用同类动作的不同情境；无复现证据不能关闭旧缺陷。
- 本轮没有游戏测试或功能交付。281/281是CJ01前轮质量分支记录，不是本轮重跑或证明趣味。详细机器证据见 [dispatch-review.json](dispatch-review.json)。

## 启用前缺口与下一步

更密集调度前需验证一轮完整小包交接，并解决跨项目容量协调；当前入口没有账号级全局并发锁，也没有脱离主代理独立验收的后台执行器。仅新增定时时间不能补齐这些能力。原自动化每日22:00继续检查有效批准；OPS01 本轮失败后不凭旧D11自动重发。

下一步仅一项：用户决定是否批准一个有限的交接稳定性试跑，再启用上述两晚节奏。它不恢复旧失败包、不批准整个候选库。

本机定时项目要求电脑开启、桌面应用运行、项目仍可访问；主代理与套餐通道也需要可用。官方文档核对日期2026-09-27：[Scheduled tasks](https://developers.openai.com/codex/app/automations/)。不能承诺无限额度或主代理不可用后仍有自动review。
