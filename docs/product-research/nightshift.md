## 状态从哪里恢复

Notion 是用户选择方向、批准阶段、验收结果的入口；Git 中的 `.claude/autopilot/mainline.md` 是执行主线，保存已确认决策、唯一当前任务和执行证据。调研目录是候选与方案的版本化记录，不是实时审批数据库。

执行主线固定保存在工作台分支 `codex/product-research-nightshift`。调研直接在此分支留档；玩法实现使用独立分支，开工时在工作台登记任务与工作分支，结束时把主线和结果摘要同步回工作台，只同步文档，不合并游戏代码。这样下次恢复不会误读旧任务。

每轮先核对用户最新决定、Git 主线与当前代码；把新的批准记录到主线后才开工。如果 Notion 访问失败、批准含糊或代码基线不明，记录具体阻塞，不用旧快照代替新授权。不运行其他已有无人值守脚本来补偿访问失败。

## 白天：只需要决定一件事

在任务表选择一项，设置「夜班许可」：

| 许可 | 夜间可交付 | 不包含 |
| --- | --- | --- |
| 未批准 | 不执行 | 所有候选均从这里开始 |
| 仅调研 | 资料、代码盘点、证据对比、最小实验方案 | 实现新玩法、迁移引擎 |
| 原型实现 | 白天已选方案的一个最小可玩增量与验证 | 未选方案、全部候选、地图 DLC |
| 修复 | 指定 bug 的最小修复与行为回归 | 顺带改写玩法或大规模重构 |

「仅调研」选择许可即可启动该任务的既定问题；「白天决定」可以补充侧重点。原型实现须写明选定方案、范围、精确代码基线及验收标准。调整执行顺序可以安排多个已批准事项，但同一轮只接一项。

调研交付后停在「待验收」。若批准下一阶段，把「夜班许可」改为「原型实现」，补齐白天决定，并将「状态」改回「可执行」；仅更改许可不会重跑待验收项。验收通过且不继续开发则设为「已完成」。

用户也可以在本任务中直接明确批准；代理须把原话含义、阶段、日期与来源链接记录到 Notion 和主线。代理不能自行把未批准项改成批准，不能把推荐、沉默或别的文档清单视为批准。

## 夜间：一次一个工作项

1. 恢复当前主线、最近两份轮次记录和 git status；拉取远端并核对批准任务的基线，不在用户正在使用的分支上直接 pull/merge。
2. 读取 Notion 最新任务。优先继续已批准、未验收的当前任务；否则从「待决策 / 可执行」且许可有效的事项中按执行顺序选择一项。待验收、已完成、暂缓、阻塞和未批准项不自动重跑。
3. 记录任务 ID、许可阶段、批准来源、基线提交、范围和验收条件；状态设为执行中。同一时间只保留一个当前任务；已有运行者时不重复启动。
4. 调研阶段生成有来源、可反驳的结论。实现/修复阶段在独立分支做最小改动，按实际变化运行必要测试，并走真实交互验收。没有玩家参与时标明「待人工试玩」。
5. 完成后用真实结果更新主线和轮次摘要，commit 并 push 到工作分支；回填 Notion 的「结果链接」和验证结果，置为「待验收」。完成调研不会自动进入实现阶段。
6. 遇到方向变化或超出范围，写回一个明确待决策问题并停止；不因当前任务完成而自动做第二个候选。

一轮目标是一个可审阅增量，不承诺一夜完成整套方向。未完成但有增量时保留执行中和下一步；连续三轮没有可验证增量时记为阻塞并暂停。外部依赖故障需写明具体原因。

## Git 与同步规则

- 本轮工作台在 `codex/product-research-nightshift`，基于 `407697b`，只包含文档与协作流程。
- 夜班只 push 自己的工作分支；不强推、不自动合并用户开发分支，不覆盖仍有未提交变更的工作区。实际合并留给明确的整合任务。
- 实现时的两个候选基线分别是 `407697b` 的经营页与 `fe36319` 的昼夜版。任务未写清基线就不猜测合并方向。
- 主线和调研记录要进入 Git；Notion 通过同一任务 ID 关联方案和结果。存在两个可编辑入口不代表有后台双向同步器，同步由每次夜间执行负责。
- 先验证并 push，再把 Notion 标为待验收；push 失败不能写成已交付。push 成功但 Notion 回填失败时保留提交哈希，下次只补回填，不重复实现。
- 合并后的目标分支或任务基线发生变化时，在主线追加迁移记录，并更新结果链接；不用旧版本测试替代新版本验收。

## 轮次记录

获准开工后，在 `.claude/autopilot/rounds/` 创建日期和任务 ID 命名的 Markdown，包含：

- 任务、许可阶段、批准来源、基线与工作分支。
- 本轮变更、真实测试/交互结果与证据路径。
- commit / push / Notion 回填分别是否成功。
- 代码事实、外部来源和待验证推断分开记录。
- 结果状态，以及恰好一个下一步。

未批准的空队列不生成无意义的提交。阶段验收需要用户判断的「更好玩」应列为人工观察，不能由代理自行宣称成立。
