# SM01：超市夜班昼夜闭环

批准：D13，2026-09-27 用户「你让它跑的大 feature 更新迭代」。从已展示的超市候选卡做成可玩功能；仅 Coding Plan，失败即停，无主模型接管或按量兜底。

**Goal:** 让同一超市每夜有不同局势，实际取货与搬货换回执产生取舍，次日市场经营接住后果。
**Architecture:** 沿用现有 UMD/Node、Backstage 物理与自动寻路、Reopening 白天行动和存档；新增小型状态，不建立第二套小游戏或经济系统。
**Tech:** 无依赖 JavaScript、Node test、现有 Canvas/DOM。

基线：`5970a022a7502d3075266cbe9051df472b16b852`。实现分支 `codex/supermarket-night-shift`，复用 `.claude/worktrees/city-journey-quality`；旧试玩服务和用户分支不动。工作台只同步文档。

## 范围与规则

1. 班次按 `(seed >>> 0 + day - 1) % 3` 的含义（先 seed 转 uint，再加 day-1）轮换 staffed / restock / blackout，三夜覆盖全部。白天免费打听可预知当夜局势。值班清扫机更警觉；补货酒桶更难控制；停电冷库锁住，需要一件可卖 €5 的零件实地修电。具体 UI 要把差异和代价说清。
2. 超市柜台位于现有入口附近 `{x:405,y:1085}`。玩家靠近并有无遮挡视线，才可选择「帮忙搬货」或「直接取库存」。选择帮忙后不能同时掠取货架 item0 和冷库 item1；选择取库存后不能反悔领取搬货回执。未选时实际拿走 item0/item1 自动视为取库存，保留旧的探索取货直觉。
3. 搬货使用现有滚动酒桶 item2，容量3格。必须实际收进包，再送到柜台；交付消耗该桶，不能再把它变成4杯酒。交付一次且只有安全撤离才得到可结算回执。放弃/获救不发回执，玩家可走其他城市路线继续取货、离开。
4. 停电用现有可修零件，不生成免费物资。到现有卸货门开关附近 `{x:735,y:1105}` 修电，消耗包内一件零件、开启冷库取货。钩索、泡沫、容量、丢弃、伤害等继续用已有规则。不得用点击选项瞬移或隔墙取物。
5. 取过 item0/item1 后，次日市场箱价由 €8 变 €10，仅持续次日；搬货回执则提供一次次日差事，消耗1次白天行动，换3杯品质1金艾尔和1酒花。取货即时收益/风险与搬货牺牲一桶换后续资源不同。回执有实际行动成本、一次领取、到期提示。没有取货/完成搬货的访问不能凭空发后果。第3夜展示最终记录，不制造不存在的第4天奖励。
6. 次日告示、当前价格、回执差事入口、夜间状态牌和收获总结都可见；黑色幽默针对库存制度和城市劳动。自动行进继续真实走路，到达后选重要动作，阅读时暂停，随时手动。满包/落物/走不通有明确恢复路径。

## 阶段一：夜探（CC；固定 ID amsterdam-sm01-night-20260927）

修改 backstage-core.js / backstage-auto.js / backstage-ui.js / backstage-scene.js，新增 test-market-shift.js。测试先红后绿。不改 Reopening、其余地点、经营数值或已有回归断言。

在现有 version4 run 增加可选 `marketShift` 子状态，自身 version1；旧档缺字段保留旧夜探行为，不在旧局中凭空加任务。新局创建该状态。状态需保存班次、单选路线、搬桶交付、是否取过库存、修电消耗的物品 ID；严格检查类型、枚举、物品/背包关联，拒绝伪造交付、重复消耗及不一致存档。不得用宽松 restore 接受任意值。

公共接口：`B.marketInfo(run)` 提供 enabled、condition、label、copy、counter、fuse、powered、approach、delivered、stockTaken 和各操作可用性。`B.command` 新动作 `market-salvage` / `market-trade` / `market-deliver` / `market-power`，仍由距离、视线、状态、实物检查决定成功。

`B.rewards(run)` 保持原有库存收益；额外可选 `market` 对象，含 condition、approach（null/salvage/trade）、delivered、stockTaken、powerRestored。delivered 是已实地交付事实，是否产生回执由调用方检查 status==='extracted'。不要在夜间提前发钱或额外库存。

自动模式可完成选路线、取酒桶、交付、修电、取冷库货和撤离。它和手动共用 command，不能通过直接改状态作弊。UI 使用真实可用性，并给出失败原因。场景有柜台、修电点和班次标识。

验收：同 seed/day 重现、三日差异；远处/隔墙拒绝、容量真实、同一桶不能双花；停电需要真实零件、不会吞无关物品；两条路线均能用实际自动 step 完成；选择暂停、存档恢复、旧档兼容、异常状态拒绝；既有夜探回归通过。

## 阶段二：昼夜联动（阶段一验收后 CC）

修改 reopening-core.js / reopening-ui.js，新增 test-market-daynight.js；如果阶段一接口需变更，先固定合同，不让两包并行改同一份代码。

新增严格、可迁移的小型 market 状态，记录有效日、涨价/待领回执、领取状态及最近后果。旧存档默认无后果。returnExplore 从真实 market reward 记后果一次；nextDay 激活、过期，准备阶段 market 箱价实际扣对应金额；新 marketErrand 动作限 prep、当天有未领取回执、actions>=1，扣行动发真实批次+酒花，一次结算且受上限约束。UI 动态价格与禁用原因一致，免费线索说明具体班次，手册/结算保留记录。

验收：完整「白天线索→夜里真实任务→回店→下一天差事/涨价」；重复点击/刷新不重复奖，未参与无后果，救援/轻装不发回执，第3夜不产生可领第4天任务；旧档与新档持续有效。全量 Node 回归，主代理独立浏览器操作自动/手动、暂停刷新与手机宽度。
