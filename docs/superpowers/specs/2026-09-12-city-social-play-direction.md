# 全城、街区与人情债：下一阶段玩法建议

日期：2026-09-12。状态：方向讨论稿，以下新增玩法尚未实现，数值与趣味需要试玩验证。本轮交付为现状核对与设计，不改变正在玩的三天存档和游戏代码。

用户明确的方向：有一个完整城市总图，再分为可探索的小地图；小地图要有 2.5D 房屋、街景、人物和互动；白天行动、夜间经营，有比现在更丰富的玩法与黑色幽默；当前网页交互可以验证初期肉鸽规则，不能直接作为最终对客体验。

## 2. 地图：先完整规划城市，再逐个做出有密度的街区

推荐分区式城市：全城总览 → 街区探索 → 从街区进入室内或专属挑战。总览和探索使用不同尺度，不能只把现在的大画布放大。

- 全城总览交代街区关系、渡轮连接、今日机会、已知人物去向和可进入区域。进入选定街区后再自由走动。远距离交通简短处理，避免每次办事都重复走空路。
- 街区使用固定斜视角，能看到建筑正面和侧面；人物能在街面前后左右移动，树木、桥栏、屋檐有前后遮挡，灯光随昼夜变化。保留清晰的入口和互动提示。正式美术在这个空间关系成立后统一。
- 室内有自己的用途：酒吧是操作空间，咖啡馆是人物与委托节点，酿造间是生产空间。进入门口切换场景，而不是所有建筑共享一张地图和右侧面板。
- 建筑位置、主要道路、人物身份固定，便于玩家形成城市记忆；随机改变开放支路、货物、委托、天气规则和到访安排。封路必须保证回店路径。

现有六个地点可归入四组内容，以下为设计分组，不代表已建成四张小地图：

| 街区 | 内容与气质 | 给经营带回什么 |
|---|---|---|
| Jordaan / 运河带 | 自家酒吧、Lotte 的桥、居民窗台、邻里与演出 | 熟客、承诺、演出机会、投诉后果 |
| De Pijp | Bram 咖啡馆、Albert Cuyp 市场、卸货巷 | 工钱、补货、消息、商户互助 |
| Noord | 码头、仓库、渡轮与水路 | 打捞物、稀有材料、设备零件 |
| Science Park | Chen 实验室、温室、样品间 | 特殊配方和有代价的试验品 |

方案取舍：分区式城市方便逐区打磨，符合当前方向；无缝全城需要大量街景和重复行走内容，现阶段成本太大；纯节点式地图制作最快，适合规则验证，但不足以承载用户想要的街景探索。

## 3. 社交：让人物参与经营，而不只是积累好感

这里先按单机 NPC 社交设计。三个熟客各有简单日程、眼前难题和能兑现的帮助；人物关系先用具体经历表达，例如“你替她保住了演出”，而不是要求玩家每天重复送礼。

- Lotte 想有付费演出的地方。帮助她能带来乐队与客人，但舞台占位置，声音会影响邻居。她会记得留酒、报酬和你是否守约。
- Bram 缺午市帮手，也有自己的订单。帮他完成真实的小委托，之后可以托他保管材料、接到团体订单或借设备；同一晚接大单会增加服务压力。
- Marta 熟悉街坊，也是会被噪声影响的居民。听她的诉求可以提前知道今晚的客群和街区动静；不能把她简化成无限提供折扣的好感商店。

先用一条三天事件链串起来：Lotte 邀请演出 → 白天得知 Marta 要求保持安静 → 选择室内不插电演出或热闹的露台演出 → 安排店内空间与备货 → 当晚客人、座位和噪声事件不同 → 次日人物在街上反馈。

两种安排都能经营成功，但需要不同准备。界面提前告知可预见代价，例如占座或投诉风险；不要求玩家靠猜隐藏数值找唯一正确选项。失约允许后续补救，不永久封死人物。

黑色幽默应从这类矛盾里出现：房东抱怨演出影响安静，随后要求按“现场演出商业用途”加租，并预留第一排。笑点落在账单和人的行为上，而且玩家有应对办法。温暖的街坊关系为荒诞提供反差。

## 4. 玩法：三种不同的乐趣，互相产生后果

**白天出门：探索、判断与带货回来。** 将打捞扩成短路线挑战：选路、操船、躲障碍、识别货物，背包满了要丢弃或返航。绕去稀有物会消耗时间；提前回去也应是合理选择。三日切片先保留两次准备行动，街区闲逛和读对话免费，开始有收益的活动才扣行动。挑战时间耗尽自动返航；失败损失本次部分收获，不抹掉已有店内库存。

**回店酿造：准备与取舍。** 从“每段都按准”增加为“今晚酿给谁”：原料决定风味，稳妥与冒险工艺影响品质、产量或副作用，保留一段有手感的短操作。失误可转成另一款适合不同客群的酒，需要重新安排菜单；不能每次只扣分。先做少量有明显区别的配方。

**晚上营业：调度与临场处理。** 玩家在酒头、座位、补货点之间移动；端酒、收杯、处理突然到店的人。双酒头、陈酿和演出应改变操作安排，不只是提高收入数字。先从两处工作站和少量座位验证，避免一开始同时加入洗杯、清洁、做菜等多条计时器。

咖啡馆、市场、实验室先做好各自的决策和事件：接什么委托、买什么货、试不试这份样品。只有出现独特且有趣的操作时才扩成独立小游戏。灰色交易、追逐等旧实验也按这个标准重新筛选。

## 5. 肉鸽：固定城市里，每一局过不同的三天

保留三天短局做验证。每局选择少量互相有关的变化：城市事件、人物难题、供应变化、可选设备。相同 seed 应固定这些安排；玩家改变路线和经营选择，才改变结果。避免只随机售价或把城市道路完全打乱。

希望逐渐形成三种能感知差异的玩法：

- 街坊小店：熟客、稳定供应、较低压力，靠回头客经营。
- 演出酒馆：为乐队备货，客流更集中、空间更紧，收益和临场压力都高。
- 试验酒坊：拿特殊原料做小批次酒，匹配愿意尝新的客人，承担副作用和滞销风险。

这是未来的验证目标，当前三种设备尚不足以证明三条玩法成立。跨局优先解锁新人物事件、配方和设备选择，不先加入必须刷很多次的永久数值加成；局内欠款、库存和临时承诺随重开重置。

## 6. 下一份可玩的交付

一个完整的 Jordaan 2.5D 街区切片：从全城总览进入，走过街道找到 Lotte 和 Marta，进入酒吧和酿造间，经码头入口体验一次短打捞，再让白天的承诺与收获改变当晚营业。其他街区在总览中有明确位置与状态，原有补给活动继续可用，独立街景逐区补齐。

先让场景中的人物、门、酒头和物件成为主要交互入口；界面保留少量资金、时间、任务提示、暂停和输入辅助。文字面板用于对话与需要比较的选择。当前网页继续作为可改动的玩法原型；正式 Unity 场景迁移是后续交付，不把本轮设计当成已迁移完成。

首个切片的规则扩展只取一条人物事件链与一个打捞变化，复用现有酿造和库存闭环。完整配方系统、三条经营玩法、跨局解锁分后续阶段验证，避免同时重做整座城市。

验收要分两层：

1. 功能：总览和街区正确往返；碰撞、遮挡和进门一致；资源与承诺跨场景不丢失；两条事件选择产生各自预告的当晚变化；刷新恢复、失败返航和三天结算可用。
2. 趣味：让未参与开发的试玩者自行找到目的地、完成第一件事；能说清白天哪个决定改变了晚上；完成一局后能主动提出下一局想换的做法。记录迷路点、重复空走和无意义操作，不能用通过的测试数量替代这些反馈。
