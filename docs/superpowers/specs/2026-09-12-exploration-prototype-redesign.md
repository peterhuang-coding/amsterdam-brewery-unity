# 探索式玩法：原型重审与重设计

日期：2026-09-12。状态：源码盘点与新原型方案；没有修改当前游戏，也没有把下述方案称为已可玩。用户明确反馈打捞、啤酒等过于简单，希望更多多样性、可能性和探索。

## 一、重新定义要验证的乐趣

当前多个原型主要验证“执行正确操作 → 获得奖励”。下一批原型要验证玩家能否通过观察和试验，发现一个地点的新入口、一个物品的新用途、一条配方规律、或一个人物没有直说的需求。

探索的收获可以是捷径、知识、人情、故事、藏品和空间变化。酒馆作为根据地串起这些经历，但不是所有活动都必须提高啤酒收入。允许为了好奇心、一个朋友或一个秘密出门。

设计判断：多样性来自可迁移的规则和不同解法。更换场景名称、增加酒款数量、随机收入倍率，并不足以证明玩家有了新的玩法。

## 二、现有原型盘点

本次范围为三个实际入口：当前 `three-day-slice/tools/prototype/index.html`、同目录 `legacy.html`、另一 worktree `amsterdam-map-refine/tools/prototype/index.html`。按入口、操作与收益路径阅读源码，未重新逐个进行浏览器实玩。历史 Unity 原型前轮已抽查，不计入当前可玩入口，也未运行验证。

| 原型 | 当前能确认的设计/实现 | 对探索的限制 | 去向建议 |
|---|---|---|---|
| 当前城市行走 | 六地点、道路碰撞、桥/渡轮、免费移动、进店面板 | 到达多为打开一个已知按钮，没有改变环境的操作 | 发展为可调查、可搬动物件、有秘密与捷径的街区 |
| 当前三航道打捞 | 换航道、窗口捕获、30 秒/三份有用收获结束 | 路线、物品用途、回收方式都很固定 | 降为入门操作；主玩法升级为空间探索与回收 |
| 当前酿造 | 两款酒、三段时机、品质与酒花加成 | 大多追求同一个“按得更准”的目标 | 短操作保留一次，主体转成能做实验的产品研究 |
| 当前夜间酒吧 | 选顾客、酒款、报价、倒酒时机、有限库存与耐心 | 物理空间与社会信息还没有进入主要决策 | 保留经济闭环，增加空间安排和特殊客人处理 |
| 当前咖啡馆/市场/实验室 | prepare 内一次性资源交换 | 没有独立探索过程 | 分别承担人物消息、交换网络、实验验证 |
| 当前社交/夜间事件 | 熟客好感、留酒承诺、固定夜间二选一 | 主要后果是预算、耐心、租金等数字 | 改为可查证的承诺、委托、人物日程与环境后果 |
| 旧版冲浪 | 浪点、浪形与修饰组合、深度区、碎片、压浪/平衡及事件 | 操作变化比新版多，但30秒结算和主题混杂限制城市探索 | 保留预告、深浅风险、运动手感的思路；融入水域探索，源码需挑选复核 |
| 旧版酿酒 | 按订单配料、隐藏目标温度、三阶段命中、品质与连击 | 主要是记住正确答案，完成后还直接加现金 | 不恢复旧奖励链；吸收有解释的材料差异 |
| 七日切片酿造/售酒 | 已有基底/风味/酵母标签、稳妥/冒险、事故保品质或产量/改酒型、批次与客群匹配 | 仍在独立分支，没接入当前三天入口；客群价值主要数值化 | 这是值得吸收的已有设计，作为实验型酿造的起点 |
| 旧版咖啡经营 | 产品、豆、工艺、客群、价格、热度及事件 | 部分风险直接标明身份，选择易变成遵循提示；与酒吧服务重复 | 留一段手感好的咖啡工作；以接触人、获取消息和订单为主要价值 |
| 旧版培养/SmartShop | 调环境参数、阶段生长、未知目标、笔记和加工关联 | 猜目标值加随机报废，未形成充分可推断的实验过程；入口关闭 | 并入校园/实验室的通用研究机制，不另开完整培养产业 |
| 旧版学术 | 选两个主题、协同加分、投稿门槛、申诉 | 选择组合后主要结算分数，没有采样、调查和验证；入口关闭 | 重设计为调查、样品与证据验证 |
| 旧版巨量标记 | 传送带1–5分类、专注/咖啡、分数与藏品 | 分类加时机重复性强；入口关闭 | 从主玩法名单移出，必要时作为短剧情桥段 |
| 旧版市场顺手拿货 | 三摊位红黄绿时机、罚款与货物 | 正确窗口拿取，环境与路线没有意义；市场入口关闭 | 不单独重做时机条，融入所有权、交涉与场地进入规则 |
| 旧版通勤/逃票 | 买票/不去、技术选择、乘车窗口和处罚 | 连续短时机，主要省钱；车站入口关闭 | 通勤承载人物相遇和路线选择；不要求每次通勤过小游戏 |
| 旧版合成/送礼/派系/心情交易 | 配方表、物品换关系、倍率与资源交换；相关快捷入口关闭 | 倾向查表、刷数值，少有新行动能力 | 合成转向工具用途；关系转向具体经历；资源献祭系统暂不进入主线 |
| 钓鱼/货运自行车等 | 当前三个入口未发现独立钓鱼或可骑货运玩法；有装饰自行车、钓鱼相关文字/物品 | 不能算已有小游戏 | 仅作候选，按独特操作和探索价值决定是否制作 |

## 三、六个值得做原型的方向

它们是候选验证单元，不是要求同时制作六个系统。先做第一项，再接其中最能产生因果的部分。

### A. 城市探险与环境操作：《被淹的仓库》

下午接到一张含糊的取货单，仓库门口贴着“请先证明本仓库存在”。正门有人值守，旁边能看到水道、封住的侧门和堆着货物的通路。目标是找到并运回一件指定设备，同时可以顺路调查其他货物。

玩家走动、观察、搬动、连接设备、使用工具、和人交涉。至少三条可行办法：从熟人处借到侧门钥匙，经陆路用推车取货；沿水道划小船进入，以较小载量分次运输；借泵排水，打开原先不能走的通道。借钥匙会留下需兑现的帮忙，划船需要实际控制与装载，排水需要设备并改变场地。

这些入口存在于地图，不在开场给“选择解法一/二/三”的列表。玩家从门口标记、工具形状、货物状态和人物话语推断。已发现的线索进入简短日志，可选提示逐级给出，不要求反复盲点。

关键组合：排水能露出地面通道，却让原本漂着的箱子落地；推车能多搬货，但过不了台阶；小船能走水路，但大件占更多空间。规则适用于其他地点的同类物件，玩家学到的东西下次仍有用。首版用离散水位/物体状态表达，无需真实流体或绳索物理。

变化来源：委托目标、场内货物、借工具条件、已预告的水位安排与人物去向；城市道路与物理规则保持稳定。基础目标始终有一条不依赖高好感或稀有工具的路；原型准备失败后也能安全离开。

### B. 人物与线索调查：《失踪的一桶酒》

三个人都说那桶酒是自己的，收货记录却指向同一家已经关门的公司。玩家看订单、找包装标记、问当事人、去现场核对时间和地点；发现新事实后，能向人物提出更具体的问题。

线索帮助判断物品身份与去向，不是随意给谁送礼就得到答案。可通过不同证据组合推进：实物标记与送货记录，或两位目击者与现场痕迹。知识来自调查，最终处理则体现立场：还给原主、谈成补偿、公开记录，关系会记住做法。拒绝继续参与也是有效退出。

趣味是“原来这句话和那个地方有关”。黑色幽默来自每个人都想把责任写进别人的表格。未来可将校园研究改成帮忙检验样品、核对设备编号或查看公开档案，让学术参与城市生活。

### C. 酿造与实验：《做出本来没打算做的酒》

借鉴七日切片已有的标签批次和事故分流。先做少量材料、两条工艺、跨日变化和小杯试验，允许玩家通过反馈推断游戏内规则。原料标签与试饮感受有稳定对应；记录应写“这次改变了什么、结果怎样”，而不只给星级。

玩家可以保留一份对照，只改变一种材料；试饮后再决定是否扩大生产。新的发现保留在笔记里，后续可复现。提供基础可靠配方和少量试验材料，不用大量付费报废来换一条隐藏答案。

不存在对所有客人都最好的酒：一种偏苦的试验品可能适合某类客人，却不适合另一场活动；也可以留下陈化或重新安排菜单。完全损坏的批次仍有明确损失，不能靠随便改名把所有失误变成更赚钱的结果。深度来自用途与条件，数十种只换名字的酒不算多样性。

### D. 修理与工具组合：《城市的废物，自己的办法》

收回来的东西可以修复、拆成零件、当作原物使用，或者交给真正需要它的人。首轮只做少量明确用途：推车搬大件；灯照亮可读线索；泵改变积水区状态。

每件工具至少在两个地方有用。升级改变能做的事，例如能运大件、能看清暗处、能走一条路，而不只给收益 +10%。限制携带空间，让出门准备有取舍；现场能借替代品，避免出错只能重开。

工具组合必须能从外观和既有规则推断，不能要求玩家把任意两件物品逐个尝试。首轮不做自由机械建造系统；新增工具需要先写出一个独特问题与至少两处用途。

### E. 市场与交换网络：《没有一种货币够用》

市场摊主有不同需求和开摊安排。玩家可以拿现金买、用修好的东西交换、接下送货委托，或者联合邻居拼单。先调查需要什么，再决定交易链和行走路线。

一条可见的链条：替咖啡馆送设备 → 获取晚间团体订单和借车机会 → 用借来的车拉回市场大件。关键回报包含服务和通行能力，不能所有中间产物都立刻自动折现。

保证现金购买等直接路线仍可行，不把所有基础材料锁在三段跑腿之后。库存与需求变化提前提供线索，已接受的委托不因随机刷新无声消失。先做两三人之间的小交换，验证是否真有判断而非重复送物。

### F. 酒馆作为社会空间：《办一场不会按计划进行的夜晚》

白天调查今晚可能到访的人，选择菜单、空间和帮手。晚上同一间店可以承接演出、邻里聚会或试饮会，各自改变玩家要照顾的人和现场安排。

玩家可以靠动手服务维持节奏，也可以从提前获得的消息中找到办法：把吵闹的人群与安静客人分开，兑现承诺让朋友帮忙，临时改成小范围演出。顾客的反应、人物关系与现场物件显示结果。

倒酒只是其中一个有手感的动作。主要选择在于“让这场夜晚成为什么样”。活动失败保留真实损失，也可能触发下一日补救故事，不能只展示收入乘了多少倍。

## 四、用一小组规则支撑可能性

首个环境原型只需要位置与通路、水位两态、物件可搬/漂浮/体积属性、工具用途和一个人情承诺。不要为六个候选一次搭建全城模拟器。

新内容接入相同规则：同类箱子遵循同一搬运限制；同一工具在不同地点有一致效果；人物只对实际发生或已传达到他的事实回应。场景中可交互对象有一致提示；装饰和玩法对象能分辨。物品改变状态后应有视觉、声音或文字确认。

“三条解法”只是最低验证标准，最终希望玩家能混合使用它们，例如借钥匙找到泵，再用排水露出的通路推车运货。应支持这些组合，不因任务脚本只预设了三条固定分支就拒绝执行。

随机性改变条件，知识与规则可积累：某次委托要轻便物件，船路就有优势；另一次搬大件，提前借车有价值。不要靠随机封死所有路制造难度。

## 五、制作选择与顺序

继续扩大小游戏合集能增加数量，但不解决解法单一；纯剧情调查更容易控制内容，却较少验证物件与空间；推荐先做环境操作与少量人物线索结合的小街区，它直接检验用户要的探索可能性。

把前轮约 15 分钟街区试制收敛到《被淹的仓库》：仍从 Jordaan 酒馆出发，沿街找线索和工具，进入一个相连的仓库区，带着物品、知识或承诺回店，再看到一次当晚/次日反馈。目标物可为店用泵或借来的设备，不必每次都是酒。

这一范围先替代“扩三航道打捞”的下一原型目标。第一轮只做环境操作、三种可混合解决办法和一名会记住承诺的人。产品研究与完整晚间活动先复用现有基线，待空间探索验证后再重做。Unity/桌面方向仍是前轮建议，本轮没有恢复或迁移引擎。

### 原型成立的证据

1. 无需开发者口头解释，玩家能看懂目标并发现一个可尝试动作；迷路时有逐级提示和明确退出。
2. 同一初始条件有三条实际可走通的办法，代价体现为操作、携带能力或人情，而不是三个名字不同的确认按钮。
3. 至少一种工具用途能迁移到第二个位置；物体与水位组合产生实际路线变化。
4. 不同试玩者或同一玩家第二次，能采用不同动作顺序，并说明为什么这样做；不依赖全图任务箭头照做。
5. 调查/工具知识、货物、人物承诺分别有可见后果；结算不自动把全部收获换成现金。
6. 功能验收覆盖物件状态、碰撞/转场、存档、重复交付和失败退出；试玩反馈独立记录。代码或测试数量不能证明已经好玩。
